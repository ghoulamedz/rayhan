# Use `@MappedSuperclass` for the consolidated order pipeline

SalesOrder / PurchaseOrder (and their lines, delivery notes, goods receipts) are near-identical structures duplicated across 8+ model files. We're consolidating them into a shared base — but we chose `@MappedSuperclass` over `SINGLE_TABLE` because the subclasses have genuinely different columns (`quantiteLivree` vs `quantiteRecue`) and different enum sets for status. `SINGLE_TABLE` would force nullable columns for every union field and a single enum column that can't be type-checked per subclass. `JOINED` was rejected because the Tiers precedent showed it adds a JOIN on every query for zero polymorphic benefit. `@MappedSuperclass` keeps separate tables, no JOINs, no NULLs, and Hibernate's `ddl-auto=update` handles schema evolution transparently since the column mappings are identical where they overlap.
